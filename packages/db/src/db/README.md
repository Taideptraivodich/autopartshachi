# Database Layer — Agent 02B.2

PostgreSQL + Drizzle ORM implementation of the schema defined in:

- `HANDOVER_AGENT_02A_DOMAIN_MODEL.md` (business source of truth)
- `HANDOVER_AGENT_02B_DATABASE_ARCHITECTURE.md` (technical source of truth: ERD, SQL, constraints, indexes)

This Agent only translated those two documents into working code. No business logic, no new entities, no relationship changes.

## Structure

```
src/db/
├── index.ts          # Drizzle instance + pg Pool (import `db` from here)
├── schema/            # Table definitions, 1:1 with 02B §2
│   ├── vehicle.ts      # vehicle_brand, vehicle_model, vehicle_generation
│   ├── product.ts      # product_brand, product_category, product, product_image, product_category_map
│   ├── oem.ts           # oem_number, oem_mapping, oem_replacement, oem_cross_reference
│   └── compatibility.ts # compatibility (Product <-> VehicleGeneration bridge)
├── relations/          # Drizzle `relations()` for the query API (db.query.*)
├── migrations/          # SQL generated by drizzle-kit — do not hand-edit
├── seed/                # Development-only seed data
└── utils/
    ├── migrate.ts        # Applies pending migrations
    └── reset.ts           # DEV-ONLY: wipes the database
```

## Setup

```bash
npm install
cp .env.example .env   # set DATABASE_URL to your PostgreSQL instance
```

## Migrate

```bash
npm run db:generate    # regenerate SQL from schema/ after any schema change
npm run db:migrate     # apply pending migrations to DATABASE_URL
```

## Seed

```bash
npm run db:seed
```

Seeds (development data only, safe to re-run — uses `onConflictDoNothing`):
`vehicle_brand`, `vehicle_model`, `vehicle_generation`, `product_brand`, `product_category`, `oem_number`.

Per 02B §5, `Product`, `ProductImage`, `OemMapping`, `OemReplacement`, `OemCrossReference`, and `Compatibility` are **not** seeded — that's real operational data entry, out of this Agent's scope.

## Reset (dev only)

```bash
npm run db:reset       # drops public + drizzle schemas — refuses to run if NODE_ENV=production
npm run db:migrate
npm run db:seed
```

## Notes on deviations from the letter of 02B

Two additive, non-structural extensions were made per the 02B.2 mission brief's "SEO Preparation" and seed-scope sections — neither adds a business entity or changes a relationship, so they don't conflict with 02A/02B being the single source of truth for business modeling:

1. **SEO fields** — `product.meta_title`, `product.meta_description`, `product_image.alt_text`, `oem_number.normalized_code` (+ its index). These aren't in 02B's data dictionary; they were explicitly requested by the implementation brief as forward-looking columns for Agent 03+.
2. **Seed scope** — 02B §5 lists only `VehicleBrand`, `VehicleModel`, `ProductBrand`, `ProductCategory` as seed targets. The implementation brief additionally lists `VehicleGeneration` and `OemNumber`, which are included here (still no `Product`/`Compatibility`/mapping data).

Everything else — table names, columns, types, constraints, ON DELETE rules, and indexes — matches 02B exactly; see the generated SQL in `migrations/0000_cheerful_pyro.sql` for the literal DDL.
